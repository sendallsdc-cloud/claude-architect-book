## 부록 B. 도메인별 치트시트

이 부록은 다섯 도메인의 판단을 표 다섯 장으로 압축했습니다. 시험 전날 이 다섯 장만 읽어도 큰 줄기는 남습니다. 다만 표는 판단의 결과만 담고 있으므로, 이유가 기억나지 않는 줄이 있으면 그 줄의 장으로 돌아가십시오. 표를 외우는 것보다 "왜 그런가"를 한 문장으로 말할 수 있는 것이 낫습니다.

각 표의 마지막 칸은 그 판단에서 자주 나오는 오답입니다. 시험지에서 그 표현이 보이면 경계하십시오. 오답은 대개 그럴듯한 원칙을 과장한 형태로 나옵니다.

### B.1 에이전트 아키텍처와 오케스트레이션 (27%)

이 도메인의 질문은 하나로 모입니다. **누가 루프를 돌리고, 언제 멈추고, 무엇을 누구에게 넘기는가.** 나머지 세부는 이 질문의 답을 구현하는 수단입니다. 함정은 대개 '더 많은 제어' 쪽에 있습니다. 반복 상한을 늘리거나, 모든 서브에이전트에 모든 권한을 주거나, 계획을 더 길게 만드는 선택지는 안전해 보이지만 비용과 실패 지점을 함께 늘립니다.

| 상황 | 판단 | 피할 것 |
|---|---|---|
| 응답의 종료 사유가 도구 호출 | 결과를 모두 넣고 루프를 계속 | 텍스트가 있으니 끝났다고 판단 |
| 종료 조건을 정해야 함 | 종료 사유와 반복 상한을 함께 | 특정 단어의 출현 여부로 종료 |
| 한 응답에 호출이 여러 개 | 모두 실행하고 아이디를 붙여 한 번에 반환 | 첫 호출만 처리 |
| 일이 여러 시스템에 걸침 | 조사 단위로 나눠 서브에이전트에 위임 | 대화 전체를 복사해 전달 |
| 서브에이전트에 넘길 정보 | 팩트 블록과 식별자만 구조화 | 도구 결과 원문 전부 |
| 서브에이전트의 권한 | 맡은 일에 필요한 도구만 | 서버 단위 와일드카드 |
| 반드시 막아야 하는 행동 | 실행 전 프로그램적 게이트 | 프롬프트 강조와 신뢰 |
| 도구 결과의 형식이 제각각 | 호출 후 훅으로 정규화 | 모델이 알아서 읽게 둠 |
| 훅이 예외로 실패 | 거부로 닫고 이유를 반환 | 허용으로 열어 둠 |
| 작업이 중간에 커짐 | 동적 분해로 다음 단계를 결정 | 처음 계획을 무조건 유지 |
| 두 전략을 비교 | 같은 지점에서 포크해 병렬 실행 | 같은 세션에서 순차 실행 |
| 실패한 일부만 다시 | 세션을 이어 받아 해당 건만 | 전체를 처음부터 재실행 |

기억할 한 줄: **멈춤은 신호로, 강제는 코드로, 위임은 요약이 아니라 사실로.**

### B.2 도구 설계와 MCP 통합 (18%)

이 도메인의 질문은 **모델이 무엇을 보고 도구를 고르는가**로 모입니다. 모델이 보는 것은 도구 이름과 설명, 그리고 입력 스키마입니다. 코드는 보지 않습니다. 그래서 코드가 아무리 좋아도 설명이 흐리면 오선택이 나고, 반대로 설명이 정확하면 서버 구현이 단순해도 선택은 맞습니다.

| 상황 | 판단 | 피할 것 |
|---|---|---|
| 두 도구의 역할이 겹침 | 겹치는 문장을 지우고 경계를 명시 | 설명을 더 길게 쓰기 |
| 도구 설명을 써야 함 | 언제 쓰고 언제 쓰지 않는지, 입출력 | "조회한다" 한 줄 |
| 도구가 실패함 | 범주·재시도 여부·힌트를 구조화 | 스택 트레이스 전달 |
| 일부만 성공 | 부분 결과와 실패 목록을 함께 | 빈 결과를 성공으로 |
| 도구가 너무 많음 | 역할별 스코프, 필요하면 검색 도구 | 모두에게 모든 도구 |
| 특정 도구를 반드시 | 제한된 상황에서만 강제 | 사람 인계 경로까지 강제 |
| 팀 전체가 같은 서버 | 저장소의 프로젝트 설정 | 각자 사용자 설정 |
| 사내망 서버를 외부에서 | 터널·인증·환경변수 확장 | 포트 직접 개방 |
| 낯선 저장소 탐색 | 넓게 찾고 좁혀 읽기 | 모든 파일 열기 |
| 파일 수정이 실패 | 다시 읽고 통째로 쓰기 | 같은 편집 반복 |

기억할 한 줄: **설명이 선택을 결정하고, 오류가 다음 행동을 결정한다.**

### B.3 Claude Code 구성과 워크플로 (20%)

이 도메인의 질문은 **같은 일을 다음 사람도 같은 방식으로 하게 만드는가**로 모입니다. 설정 파일은 그 답을 저장소에 남기는 수단입니다. 함정은 '문서를 더 쓰는 것'입니다. 규칙을 늘리면 읽히지 않고, 읽히지 않는 규칙은 없는 것과 같습니다. 문서를 늘리는 대신 스킬과 훅으로 옮기십시오.

| 상황 | 판단 | 피할 것 |
|---|---|---|
| 팀 규칙을 둘 곳 | 저장소 루트의 프로젝트 문서 | 사용자 수준 문서 |
| 규칙 문서가 길어짐 | 핵심만 남기고 상세는 import·스킬로 | 한 파일에 계속 추가 |
| 반복 절차를 자동화 | 사용자가 부르면 커맨드, 모델이 판단하면 스킬 | 둘을 같은 것으로 취급 |
| 스킬을 많이 만듦 | 설명을 짧고 서로 다르게 | 설명에 절차 전체 |
| 디렉터리별 관례 | 경로 glob 규칙 | 조건문을 루트 문서에 |
| 넓은 변경 | 계획 모드로 조사·승인 | 바로 실행 |
| 한 글자 수정 | 바로 실행 | 계획 모드 |
| 출력 품질이 매번 다름 | 입출력 예시와 테스트 먼저 | 모델 상위로 교체 |
| 요구가 모호함 | 결정할 세 가지를 확인 | 추측 구현 |
| CI에서 자동 실행 | 프롬프트 인자, JSON 출력 | 대화형 세션 |
| 리뷰 오탐이 많음 | 근거 요구와 신뢰도 임계 | 지적 수 늘리기 |
| CI 권한 | 읽기 전용, 코멘트만 쓰기 | 관리자 토큰 |

기억할 한 줄: **규칙은 문서에, 절차는 스킬에, 금지는 훅에, 검사는 CI에.**

### B.4 프롬프트 엔지니어링과 구조화 출력 (20%)

이 도메인의 질문은 **원하는 것과 원하지 않는 것의 경계를 얼마나 분명히 적었는가**로 모입니다. 좋은 프롬프트는 감탄을 부르는 문장이 아니라, 두 사람이 같은 답을 내게 하는 문장입니다. 함정은 '더 강하게'입니다. 금지를 늘리고 예외를 촘촘히 적으면 문장은 길어지고 판단은 오히려 흐려집니다.

| 상황 | 판단 | 피할 것 |
|---|---|---|
| 판단 기준을 써야 함 | 범주별 조건과 예시, 경계 규칙 | "보수적으로" |
| 심각도를 정해야 함 | 등급별 기준·예시·경계 처리 | 등급만 나열 |
| 판단이 갈리는 사례 | 모호한 사례 두세 개와 이유 | 전형적 성공 사례만 |
| 출력 형식을 고정 | 도구 호출과 JSON 스키마 | 자연어로 부탁 |
| 값이 없을 수 있음 | nullable과 null | 0이나 빈 문자열 |
| 목록 밖의 값 | 기타 항목과 원문 값 보관 | 가장 가까운 값으로 변환 |
| 형식은 맞고 의미가 틀림 | 필드 간 교차 검증 | 스키마만 믿기 |
| 검증 실패 | 구체적 오류와 원문 구간을 주고 재시도 | "다시 해 보세요" |
| 재시도가 무효 | 원문에 없는 값 요구 | 횟수만 늘리기 |
| 대량·비긴급 | 배치와 항목 아이디 | 실시간 요청 반복 |
| 리뷰 품질 | 다른 인스턴스, 파일별+통합 | 같은 인스턴스 재검토 |

기억할 한 줄: **기준이 없으면 태도가 되고, 스키마가 있어도 의미는 따로 봐야 한다.**

### B.5 컨텍스트 관리와 신뢰성 (15%)

이 도메인의 질문은 **긴 대화와 실패 속에서 무엇을 잃지 않는가**로 모입니다. 잃으면 안 되는 것은 조건, 근거, 그리고 실패의 이유입니다. 함정은 '전부 기억하기'와 '전부 버리기' 사이에 있습니다. 둘 다 컨텍스트를 사실의 저장소로 착각한 선택입니다.

| 상황 | 판단 | 피할 것 |
|---|---|---|
| 대화가 길어짐 | 팩트 블록 유지, 원문 구간 보관 | 요약으로 앞부분 대체 |
| 오래된 도구 결과가 쌓임 | 결과를 걷어내고 사실만 남기기 | 전부 유지 |
| 고객이 사람을 요청 | 즉시 인계 패킷 | 자동 해결 재시도 |
| 규정에 답이 없음 | 정책 공백으로 표시하고 인계 | 임의 해석 |
| 워커가 실패 | 상태·데이터·오류 세 칸 보고 | 빈 결과로 처리 |
| 접근 실패와 빈 결과 | 오류 범주로 구분 | 둘 다 실패 |
| 자료가 매우 많음 | 목록 파일과 스크래치패드 | 전부 컨텍스트에 |
| 검토 인력이 한정 | 층화 표본과 신뢰도 라우팅 | 전부 검토 |
| 출처가 상충 | 병기하고 기준일·정의 주석 | 평균이나 임의 선택 |
| 값의 근거가 필요 | 필드마다 원문 구간 저장 | 요약문만 보관 |

기억할 한 줄: **조건은 고정하고, 근거는 구간으로 남기고, 실패는 이유와 함께 넘긴다.**

### B.6 다섯 줄 요약

시험 전날 이 다섯 줄만 읽어도 좋습니다. 각 줄이 한 도메인의 중심입니다.

- 에이전트는 신호로 멈추고, 강제는 코드가 한다.
- 도구의 설명이 선택을 만들고, 오류가 다음 시도를 만든다.
- 규칙은 저장소에, 절차는 스킬에, 금지는 훅에 둔다.
- 기준 없는 판단은 재현되지 않고, 스키마는 의미를 보증하지 않는다.
- 조건과 근거와 실패 이유를 잃지 않으면 긴 대화도 견딘다.
